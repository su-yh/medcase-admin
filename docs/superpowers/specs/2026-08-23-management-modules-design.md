# 管理端病例与医生模块设计

## 目标

在管理端实现两个已配置菜单对应的页面：

- 病例管理 / 病例审核：提供病例分页查询、条件筛选和操作列。
- 系统管理 / 医生管理：提供医生查询列表和操作列，为后续操作需求预留入口。

## 页面路径

- `src/views/case/review/index.vue`
- `src/views/biz/doctor/index.vue`

菜单通过现有后端动态路由加载，页面组件路径与菜单配置保持一致。

## 病例审核

### 查询条件

- 病例编号
- 病例标题
- 病例状态

病例状态使用后端已有枚举语义：

- 草稿
- 待审核
- 审核失败
- 审核通过 / 待结算
- 已结算

页面统一使用“病例状态”命名，不使用“审核状态”，因为状态覆盖病例完整生命周期。

### 列表字段

- 病例编号
- 病例标题
- 提交医生
- 状态
- 提交时间
- 操作

### 交互

- 使用项目通用查询表单、表格、列显隐工具和分页组件。
- 查询和重置会将页码重置为第一页。
- 分页支持切换页码和每页数量。
- 操作列先提供查看入口；待后续审核规则明确后再补充审核动作。
- 详情先使用弹窗展示病例基础信息、状态、备注、附件和审核原因等可用字段。

## 医生管理

### 查询条件

- 医生姓名或昵称
- 登录账号
- 手机号
- 状态

### 列表字段

- 医生编号
- 医生姓名
- 登录账号
- 所属科室
- 职称
- 手机号
- 状态
- 创建时间
- 操作

### 交互

- 支持查询、重置、分页。
- 操作列保留查看和更多操作入口。
- 当前不实现新增、编辑、启停用、重置密码等具体业务动作，避免提前固化未确认的规则。

## 数据层边界

当前后端没有管理端医生查询和病例审核查询接口，因此本次页面先使用页面级 mock 数据完成可操作的查询、筛选、分页和弹窗展示。

mock 数据和筛选逻辑只放在各自页面或同目录的局部数据模块中，不修改全局请求封装，也不伪造后端 API 文件。后续接口确定后，只替换页面数据访问函数，保留表格和交互结构。

## 验证

- 管理端生产构建通过。
- 两个菜单路径可以被动态路由解析并正常渲染。
- 病例审核的状态筛选、查询、重置、分页和查看弹窗可操作。
- 医生管理的查询、重置、分页和操作列可操作。
- 不修改后端和医生端仓库。
